12. Section Empty State

Standard empty state for content sections

Departmental wallets coming soon
Usage rule

Every section-level empty state uses one borderless shimmering area with a visible icon and one short status line. Do not shimmer the text itself. Avoid extra descriptions, CTA buttons, nested cards, or decorative empty-state content unless the workflow specifically requires them.

<div class="section-empty-state"> <div class="section-empty-state__content"> <i class="ph ph-wallet"></i> <span>Departmental wallets coming soon</span> </div> </div>

Motion system

WPCC motion is subtle, spatial and consistent. Animation should communicate navigation hierarchy and interaction state without competing with content.

Screen 210ms · fade + 10px rise
Surface 220ms · first 4 groups · 40ms stagger
Overlay 160–220ms · fade + anchored entrance
Preset Timing Behavior
Screen forward 210ms Opacity 0→1 with 10px upward entrance. Use for normal navigation.
Screen back 190ms Opacity 0→1 with a restrained 7px reverse entrance.
Surface 220ms Animate only the first 2–4 visible content groups; stagger by 40ms.
Menu 160ms Opacity + 4px translate + 0.975 scale from the trigger side.
Bottom sheet 220ms Backdrop fades in while sheet rises approximately 22px.
Prayer fullscreen 260ms Calm fade; timer and playlist may rise only 6px. Avoid dramatic scaling.
Tap feedback 140–170ms Small scale to ~0.96–0.985 depending on control size.

Headers should appear immediately and never bounce. Horizontal rails do not receive entrance motion. Persistent bottom navigation stays in place; only the active state transitions. Always support prefers-reduced-motion by removing translation/stagger and using a short fade.
