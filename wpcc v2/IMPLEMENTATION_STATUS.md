## Backend work already applied

- Community-safe Department/member/leadership projections.
- Same-department authorization for public member phone/details.
- Department Attendance event list and ranked present-member RPCs.
- Private R2 Department Files with `members` / `leaders` visibility.
- Devotional post/reaction/comment hardening and synchronized counts.
- Server-synced Prayer Alerts tables, occurrence/delivery/session RPCs and Web Push worker.
- Prayer vibration + snooze preference; snoozed occurrence is created with PostgreSQL `now()`.
- Non-personal/global reminders remain read-only in the member app; no unsupported admin editor was invented.
- Attendance geofence hardening; `attendance.created_at` is authoritative check-in and clock-out uses server time.
- Giving accounts/projects/transactions/recurring mandates and Paystack initialize/verify/webhook/Auto Give worker foundation.

## Server-time invariant

Flutter never sends authoritative check-in, prayer-session, delivery, payment-status or audit timestamps. User-selected event/prayer schedule dates/times are preferences. Activity timestamps are generated by PostgreSQL or trusted Edge infrastructure.

## Deployment-only configuration still required

These are configuration/activation items, not missing application screens:

- production `APP_ORIGIN`
- `VAPID_PUBLIC_KEY` in the Flutter build
- `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `PRAYER_DISPATCH_SECRET` in Supabase Edge Function secrets
- `PAYSTACK_SECRET_KEY` and `WPCC_GIVING_WORKER_SECRET` in Supabase Edge Function secrets
- scheduler/cron invocation for Prayer Push and Auto Give workers
- Paystack webhook URL configured to the deployed `paystack-webhook` Edge Function

## Validation limitation in this build environment

The current execution container has no Flutter/Dart SDK, so `flutter analyze`, `flutter test`, and `flutter build web` cannot be honestly reported as executed here. A GitHub Actions workflow is included to run all three on a standard Flutter environment.

## Continuation hardening
- Events list now loads upcoming events in 20-row pages with an explicit Load more state.
- Search announcement results deep-link to the approved Home announcement surface rather than inventing a new announcement-detail route.
- Prayer alert preferences now persist supported vibration and snooze settings; snooze occurrence time is generated by PostgreSQL only.
- `process-auto-give` worker Edge Function source/deployment is included for Paystack reusable-authorisation recurring charges.
- Department wallet account duplication is guarded server-side with a scope/target/account-number unique index.
